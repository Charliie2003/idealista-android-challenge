# ADR-0003: Add Material Components, introduce :core:design, and migrate design system

**Status:** Accepted  
**Date:** 2026-07-29

---

## Context

The project was bootstrapped with `Theme.AppCompat.Light.NoActionBar` and placeholder blue/purple colors generated by Android Studio. Three problems blocked moving forward:

1. **AppCompat theme is insufficient for M3 XML.** `MaterialCardView` and other Material3 widgets require M3 theme slots (`colorPrimaryContainer`, `colorSurfaceVariant`, `colorOutline`, etc.) that AppCompat does not provide. Without the M3 parent, those slots default to white/black, producing visually broken cards in the listing screen.

2. **The Compose theme had no home.** The boilerplate `IdealistaChallengeTheme` generated by Android Studio lived in `:app/ui/theme/`. Composables live in feature modules; feature modules cannot depend on `:app` (that direction is forbidden by the module boundary rules).

3. **The design system is shared infrastructure, not a feature concern.** Both `:feature:list` (XML) and `:feature:detail` (Compose) belong to the same product design language. Features cannot depend on each other, so placing the Compose theme in `:feature:detail` would block any future Compose component in `:feature:list` from accessing it. Design tokens are infrastructure — they belong in `:core`.

---

## Decision

### New module: `:core:design`

A new `com.android.library` module that owns all Compose design-system tokens:

- `Color.kt` — `Color(0xFF…)` constants for all DS tokens (brand, surfaces, text, favorites, energy A–G) in both light and dark variants.
- `Type.kt` — 9 named `TextStyle` values (PriceXL → Overline) and an `IdealistaTypography: Typography` object mapping them to M3 slots.
- `Theme.kt` — `IdealistaTheme` composable wrapping `MaterialTheme` with the brand color schemes. Dynamic color is disabled.

**Dependency rule:** `:core:design` depends on nothing in the project. Feature modules declare `implementation(project(":core:design"))` when they need the Compose theme. This follows the same pattern as `:core:domain` for domain types.

**XML resources** (`colors.xml`, `dimens.xml`, `type.xml`) remain in `:app/res/values/`. Android merges resources transitively; all modules inherit them without an explicit dependency.

### `com.google.android.material:material:1.12.0`

Added to `:app` and `:feature:list`. Provides:
- `Theme.Material3.Light.NoActionBar` / `Theme.Material3.DayNight.NoActionBar` as XML theme parents.
- `MaterialCardView` and other M3 widgets for the XML listing screen.

**AppCompat alone** was rejected: it lacks M3 color slots required by M3 widget components.

### No Inter font package

The DS accepts Roboto (`sans-serif`) as a zero-dependency fallback. Packaging Inter adds ~300 kB and a downloadable font XML for no visible difference on devices that ship Roboto. Can be added later via `res/font/inter.xml` (Google Fonts) with its own ADR.

### Dynamic color: disabled

`IdealistaTheme` does not pass a `dynamicColorScheme`. Idealista's green (#00A650) is brand identity and must not be replaced by Android 12+ wallpaper color extraction.

---

## Consequences

- `:core:design` is a new module in the dependency graph. It has no project dependencies — it cannot create a circular dependency.
- `:feature:detail` removes its own `ui/theme/` package and declares `implementation(project(":core:design"))`.
- `:feature:list` can declare `implementation(project(":core:design"))` when it introduces any Compose component, without any architectural change.
- `Theme.IdealistaChallenge` (XML) now extends `Theme.Material3.Light.NoActionBar`, enabling correct slot resolution for all M3 XML widgets.
- The old boilerplate `Color.kt`/`Theme.kt`/`Type.kt` in `:app` are deleted — they were dead code.
